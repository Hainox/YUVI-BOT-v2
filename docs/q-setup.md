# `/q`: поиск по истории

`/q` использует два вызова OpenAI-совместимого LLM-провайдера и локальный NLP-сервис:

1. первый вызов возвращает три разговорные переформулировки;
2. оригинал и варианты проходят через локальный `BAAI/bge-m3` (1024 измерения);
3. по каждому вектору выполняется `top-15` поиск в `message_embeddings_bge`, затем хиты объединяются по максимальной похожести;
4. ILIKE-слой ищет значимые слова с грубым корнем, а `@username` ограничивает автора и увеличивает лимит лексических хитов втрое;
5. к 25 хитам добавляются соседи `±2`, после чего контекст сортируется хронологически;
6. второй вызов формирует ответ по контексту, но может отвечать самостоятельно, если найденные фрагменты не по теме.

## Модель

В текущем каталоге OpenCode Go проектный бенч 2026-08-16 выбрал `gpt-5.6-luna`; она стоит в `OPENAI_MODEL`, `AI_STRUCTURED_MODEL` и `AI_Q_MODEL`. Модель можно заменить через `AI_Q_MODEL` или общий `/model_set`. Grok не был выбран как дефолт: текущий OpenCode Go endpoint не поддерживает модели Grok. Для прямого xAI/OpenRouter endpoint нужно отдельно указать соответствующий `OPENAI_BASE_URL`, ключ и модель из актуального каталога провайдера.

## Локальный запуск

В `.env` должны быть заданы:

```dotenv
OPENAI_BASE_URL=https://opencode.ai/zen/go/v1
OPENAI_API_KEY=ваш_ключ
AI_Q_MODEL=gpt-5.6-luna
AI_ALLOW_EXPLICIT_LANGUAGE=true
NLP_EMBEDDING_MODEL=BAAI/bge-m3
```

Пользовательские Windows-переменные `OPENAI_API_KEY` и `OPENAI_BASE_URL` очищены, поэтому они больше не переопределяют `.env` в новых терминалах. Уже открытый терминал/IDE нужно перезапустить, чтобы он получил обновлённый environment block.

Мат и explicit-выражения разрешены в AI-ответах при `AI_ALLOW_EXPLICIT_LANGUAGE=true`: они сохраняются из контекста и могут использоваться моделью, если подходят стилю чата. Администратор может переключать режим без перезапуска командами `/explicit_on` и `/explicit_off`. Это не отключает защиту от травли и дискриминации.

Миграция `0024_q_bge_embeddings` пересоздаёт старую таблицу эмбеддингов пустой: это необходимо, потому что векторы mpnet-768 нельзя использовать в пространстве BGE-M3-1024. После запуска миграций `embed_worker` постепенно заполнит таблицу заново.
