# Yuvi Arena — план разработки

**Связанный документ:** `FIGHTING_SPEC.md`
**Статус на 2026-08-07:** Фазы 0–4 и базовый Mini App lobby-срез реализованы. Phase 4 доставляет серверную PvP-сессию, authenticated REST/SSE runtime и экран `/arena/match/[id]`; settlement, рейтинг, XP и полноценные визуальные ассеты остаются следующими фазами.

## Фактическая карта текущей реализации

| Область | Сейчас в репозитории |
|---|---|
| Mini App entry | `/arena` и плитка в `miniapp/src/routes/+page.svelte` |
| Lobby list | `GET /api/v1/arena/matches` |
| Own match recovery | `GET /api/v1/arena/my-matches` |
| Match lifecycle | `POST /api/v1/arena/matches`, `/accept`, `/confirm`, `/cancel` |
| Fighter selection | 4 бойца, данные из `common/arena/fighters.py` |
| Money safety | `economy_service`, idempotency keys, transaction rollback |
| Privacy | чужой fighter скрыт до active; runtime API проверяет участника |
| Runtime | Redis-backed backend session, authenticated REST/SSE API и `/arena/match/[id]` Mini App combat screen подключены |
| Settlement/rating/XP | целевая часть ТЗ, следующий этап |

Фактические API-маршруты lobby являются источником истины для текущего среза. В старом плане ниже `GET /api/v1/arena/lobby` следует читать как целевой агрегированный endpoint; он пока не реализован и не используется Mini App.

**Репозиторий-цель:** `YUVI-BOT-v2`
**Подход:** вертикальные срезы, сначала серверная безопасность и деньги, затем визуальный слой

## Фаза 2. PostgreSQL-модели и миграции

**Цель:** сохранить игроков, бойцов, матчи, исходы и аудит.

### Минимальные сущности

- `arena_profiles` — рейтинг, общие метрики;
- `arena_fighter_progress` — XP/уровень/косметика по user + fighter;
- `arena_matches` — участники, ставки, статусы, timestamps, outcome;
- `arena_match_events` — ключевые события и replay лучшего боя;
- `arena_match_actions` — только если потребуется аудит действий; объём ограничить политикой хранения;
- `arena_leaderboard_snapshots` — недельные срезы;
- `arena_daily_awards` — защита от повторной выдачи;
- `arena_weekly_awards` — защита от повторной выдачи;
- `arena_admin_audit` — обязательный аудит ручных действий;
- `arena_fund_ledger` — журнал фонда Arena.

### Инварианты БД

- уникальный match idempotency key;
- уникальная выплата/возврат на матч;
- участник не может быть дважды в одном матче;
- нельзя принять собственный матч;
- статусные переходы ограничены;
- суммы неотрицательны;
- денежные значения integer/bigint;
- timestamps timezone-aware.

### Проверка

- миграции на чистой БД;
- rollback/forward smoke test;
- конкурентное создание/принятие матча;
- тест уникальных ограничений.

## Фаза 3. Финансовый контур и матч-лобби

**Цель:** безопасно создавать, принимать, отменять и закрывать матчи до настоящего боя.

### API

```text
GET  /api/v1/arena/matches
GET  /api/v1/arena/my-matches
POST /api/v1/arena/matches
POST /api/v1/arena/matches/{id}/accept
POST /api/v1/arena/matches/{id}/confirm
POST /api/v1/arena/matches/{id}/cancel
```

### Задачи

- минимальная ставка 100;
- отсутствие верхнего лимита, но явное подтверждение суммы;
- разные ставки;
- блокировка средств;
- 5-минутное истечение открытого матча;
- 15-секундное подтверждение;
- отмена создателем до принятия;
- возврат при ошибке;
- идемпотентность;
- отображение только разрешённых полей в лобби;
- скрытие бойцов до старта;
- фильтр рейтинга по желанию.

### Проверка

- недостаток баланса;
- отрицательная/дробная/огромная сумма;
- двойной accept;
- accept собственного матча;
- истечение срока;
- отмена после accept;
- повторный refund;
- нельзя извлечь скрытого бойца через API.

## Фаза 4. PvP-сессия и серверное состояние

**Цель:** подключить движок к двум игрокам и обеспечить 90-секундный бой.

### API

```text
GET  /api/v1/arena/matches/{id}
POST /api/v1/arena/matches/{id}/actions
GET  /api/v1/arena/matches/{id}/events
POST /api/v1/arena/matches/{id}/forfeit
```

### Задачи

- Redis state для активного матча;
- серверный clock/deadline;
- сбор действий обоих игроков в фазе;
- автоматический skip после 3 секунд;
- расчёт outcome доменным движком;
- публикация событий через SSE;
- reconnect с текущей фазой;
- 15-секундный disconnect timeout;
- техническое поражение;
- оба отключились → refund;
- блокировка повторных действий и replay attack;
- расчёт финального исхода один раз.

### Проверка

- два параллельных клиента;
- позднее действие;
- дублирующее действие;
- действие чужого пользователя;
- истечение 90 секунд;
- reconnect;
- один/оба disconnect;
- crash/restart API с восстановлением состояния.

## Definition of Done первого PvP-релиза

- PvP матч от создания до результата проходит в Mini App;
- ставки блокируются, выплата/возврат выполняются ровно один раз;
- сервер является источником истины;
- бой длится максимум 90 секунд;
- все правила из `FIGHTING_SPEC.md` покрыты тестами;
- disconnect/reconnect работает;
- рейтинг и XP не дублируются;
- есть история и лидерборд;
- администратор может увидеть и исправить зависший матч;
- все ручные исправления имеют audit log;
- frontend check/build и backend тесты проходят.
